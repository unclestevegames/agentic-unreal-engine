# The Claude Code harness on Windows

- **Git Bash rewrites an argument starting with `/` into a Windows path** - `gh pr create --title "/plan-architecture ..."` lands as `C:/Program Files/Git/plan-architecture ...`. A project's settings may refuse the direct spellings without naming the fix, and refuse the `MSYS_NO_PATHCONV=1` prefix too: pass a slash-led title from PowerShell. A title in a variable or `$(...)`, or with a double space before the quote, gets past the refusal and still lands garbled.
- **Before a handoff, find what is still running from the process list, never from known names or a log** - shell processes with their command lines and start times (`Win32_Process`), compared with the session's task output files, and `TaskStop` on the leftover. An agent "waiting on its own background work" is an open question, and an empty log search proves nothing.
- **A fresh process for a probe is the extension's bundled binary**, because `claude` is not on PATH: `~/.vscode/extensions/anthropic.claude-code-*/resources/native-binary/claude.exe -p "<question>" --model <cheap> --no-session-persistence`. The last flag keeps the probe's prompt out of the messages a performance review reads as the owner's. `--setting-sources user` is the control that ignores the project's settings.

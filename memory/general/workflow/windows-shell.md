# Scripted edits and PowerShell

- **`cd`/`Set-Location` does not move .NET's directory**: after `cd Source\Game`, `[IO.File]::ReadAllText('X.h')` resolves against the repo root, fails, leaves `$t` null, and `WriteAllText('X.h', $t)` creates an empty `X.h` at the root - the orchestrator's own commands as much as an agent's. Never `cd`; build every path absolute. A stray found later cannot be deleted without the owner's word.
- **Use the Edit tool for text substitution in any file containing non-ASCII, even a mechanical rename.** A PowerShell whole-file rewrite mangles UTF-8 into mojibake. It surfaces as unrelated string-comparison test failures, not a build error.
  - Detect: `git diff --numstat` immediately after any scripted rewrite — a whole-file line count where you expected a handful means the encoding moved.
  - Reverse deterministically: read back as UTF-8, `GetEncoding(1252).GetBytes(...)`, `UTF8.GetString(...)`, write with a BOM-less `UTF8Encoding($false)`. This keeps the intended edit, where `git checkout --` would destroy it.
- **A source file meant to carry a non-ASCII character as a `\uXXXX` ESCAPE needs its bytes checked after the edit** - an edit tool can resolve the escape in its own argument and write the raw character instead, which is the mojibake risk the escape was there to avoid. Assert zero bytes >127 in the file, not that the edit "looks right".
  - **Doubling the backslash does not rescue it** - `\\u00B7` lands as a literal double backslash, so neither spelling round-trips. Build the six bytes without ever typing the token: `[string]::Concat([char]92, "u00B7")`, or write the whole line from a script.
- **Line endings can be mixed FILE BY FILE in one repo.** Detect per file (`b.count(b"\r\n")`) and write back what was there; assuming either one rewrites every line of the other kind.
  - **A newly CREATED file has nothing to detect, so it takes its neighbours' convention.** An agent writes LF by default and the build never complains, so check it before committing - git normalises on the next touch and the churn lands in someone else's diff.
  - **Git Bash `sed -i`, and a Python text-mode read plus a `newline=""` write, each rewrite the WHOLE file LF** while `core.autocrlf` hides it from `git diff`/`--numstat`. Edit in place with Python `rb`/`wb`, then count the CRLFs.
- A scripted rewrite that changes a wrapped COMMENT's line count leaves the remainder as bare code, and the compiler error names an identifier you never wrote. Keep the replacement's line count equal, and sweep `grep -n "^ [A-Za-z]"` over touched files — `--numstat` does not catch this.
- `Set-Content -Encoding utf8` writes a BOM (into commit subjects and `.cpp` files alike); `-Encoding ascii` silently destroys any non-ASCII already there. Author commit messages with the Write tool into the scratchpad and pass the path to `git commit -F`, then verify the commit landed. The Write tool keeps a BOM the file already has, so never overwrite a message file another tool created - write a fresh path.
- Use `--body-file` for every gh body or comment — PS 5.1 mangles multi-line text with embedded quotes as native-command arguments.
  - **Never round-trip an issue body through a PowerShell variable.** `gh issue view --jq .body` lands as an ARRAY of lines, and `$body + $extra` rejoins it with spaces — the whole issue collapses onto one line, silently, and the edit succeeds. Read to a file and write from a file; if you must rebuild one, diff your reconstruction against the live body sentence by sentence before posting.
- VSCode `tasks.json` on Windows: use `"type": "process"` with a plain unquoted `command` path and each argument its own `args` element. `"type": "shell"` with a manually double-quoted `Program Files` path breaks VS Code's quoting layer and splits the path on its first space.
- Omitting a `Mandatory=$true` parameter HANGS forever rather than erroring — PowerShell prompts on stdin and nothing answers. `run-ue-python.ps1` needs `-Project` AND `-Script`. Tell: zero output at all, not even engine startup spam.
- **A quoted heredoc still collapses one backslash level**, so `[\\/]` in a regex becomes `[\/]` (just `/`, matching nothing you meant) and a two-backslash literal never matches. Build them as `chr(92)`, or write the script to a file and run the file.
  - Worst where the victim is a WINDOWS PATH being written into a generated file: `"data\\build-stamp.json"` became `data` + 0x08 + `uild-stamp.json`, which compiles, runs, and silently writes to a mangled name nothing ignores. Grep any generated file for control bytes before believing it.
- A "did this identifier leave X?" grep gate must target the DECLARATION form (`enum class Foo`, `int32 Foo`), never the bare identifier — an identifier legitimately survives a correct extraction via return types, accessor-name substrings and pointer comments.
- **A PowerShell script no build compiles is only proven by parsing it** - `[System.Management.Automation.PSParser]::Tokenize` after every edit, or a syntax error waits for the human's first run. `\"` is not an escape in a double-quoted string; backtick is.
  - **Never put a double quote inside a command string handed to a native exe** (`ssh`, `gh`) - PS 5.1 eats them and the far side sees broken syntax, which surfaces as the REMOTE tool's error. Route every literal through argv and stdout instead: `python3 -c '...sys.argv[2]...' file key > file.tmp && mv file.tmp file` needs none. Single quotes pass through fine.
- **Count BYTES on disk, never through a text-mode read** — Python's universal newlines turn CRLF into one byte, so a text-mode length under-reports by one per line and a budget measured that way is wrong by whole lines. Use `(Get-Item f).Length` or read `rb`.
- `FFileHelper::Save*ToFile` defaults to `EEncodingOptions::AutoDetect`, which switches to UTF-16 the moment the string stops being ASCII — a committed text file silently becomes a binary blob no diff can read. Pass `ForceUTF8WithoutBOM` for anything that lands in git.
- CRLF warnings on `git add` are autocrlf noise. `LogWindows: Error: Visual C++ redistributable ... outdated` and UE's `LogTemp: Error test: UE::UnifiedErrorTest::...` startup lines are benign.
- **`[System.IO.File]::Replace($a, $b, $null)` throws "The path is not of a legal form"** - PowerShell binds `$null` to a string parameter as `""`. Use `Move-Item -Force`, which is one call whether or not the target exists and still goes through MoveFileEx.
- **Never put a Windows path in a `sed` replacement** - GNU sed reads `\L`/`\U` as case conversion and drops other backslashes, so `Packaged\Windows\Logs` lands as `PackagedWindowsogs` with no error. Write path-bearing text with Python.

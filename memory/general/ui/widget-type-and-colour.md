# Type and colour in a widget

Which face and size a widget's text takes, sizing a column to its text, and choosing a UI colour.
Importing a font is `../unreal/fonts.md`.

- **Slate's `Font.Size` is POINTS AT 96 DPI - it renders 1.333x the em a font library reports.** Solve a size against the art in em, then multiply by 0.75 before it becomes a `Font.Size`, or everything draws a third too large. Confirm with `FSlateFontMeasure::Measure` rather than trusting either number.
- **A text block nobody sized draws at `UTextBlock`'s stock 24**, and so does a rich style built from `GetDefault<UTextBlock>()->GetFont()`. A size census greps `ConstructWidget<UTextBlock>`/`<URichTextBlock>`, never `Font.Size` alone, or the unsized ones are invisible to it.
- **A page is set in ONE face, and a number on it takes that page's own figures.** Two faces at one nominal `Font.Size` are not one size (x-height/em differs per TTF), so a second face for the digits alone is the wrong repair; a page that needs lining figures throughout takes a lining face for the whole page.
- **A `UTextBlock` starting from `GetFont()` inherits the stock style's typeface name, which is Bold** - and a font that really holds a Bold renders bold, silently. Every run says which face it wants, or none of them do.
- **Centring a run means point-anchoring it, not aligning it.** A vertical box packs an Auto slot against its top, and a child given `Fill` draws at the top of what it is given - so neither alignment centres anything. A `UCanvasPanelSlot` point anchor with alignment (0.5, 0.5) does.
- **A centred line box is not a centred glyph.** A face with OLDSTYLE figures hangs 3, 5, 7 and 9 below the baseline, so two different digits ride at two different heights on the same icon. Measure the ink in a capture and offset the slot; the metrics alone understate it.
- **A fixed-width column is solved against its heading's own measured advance, never by eye** - Slate does not clip a `USizeBox`'s overflow, so a too-narrow column silently bleeds into its neighbour and swallows whatever sat there. Measure with the face's own metrics: em in slate units = `Font.Size / 0.75`. A sortable heading's width is its label PLUS the caret slot it reserves, or the caret pushes it into the next column.
- **A text cut short with "…" needs `SetClipping(ClipToBounds)` on the text and LEFT justification**: `ETextOverflowPolicy::Ellipsis` only fires on clipped text, and Slate puts the "…" on the side away from the justification, so a right-justified name reads "…WWW". Hug the right side with the parent slot's `HAlign_Right` instead (saves a wasted visual pass).
  - **Predict it at planning time by parsing the TTF's own `hmtx`/`cmap`** — `sum(advances)/unitsPerEm * Font.Size/0.75` lands within a few slate units of `FSlateFontMeasure`, so a column width needs no editor round trip to plan.
- **A scroll bound production itself needs is computed from font metrics, never by forcing a layout pass.** `FSlateFontMeasure` is a real measurement and answers the same headless as in play; `ForceLayoutPrepass()` silently no-ops without a live `SWidget`, so making it work means calling `TakeWidget()` from production — which lands on the input path and charges every press in every menu for something only a spec needed. (Only a number NOTHING in production needs may be read back off `GetDesiredSize()` a tick later, leaving the maths to a hand test.)
- **A `UTextBlock` line lays out at `GetMaxCharacterHeight + |ShadowOffset.Y| + OutlineSize`, and `UTextBlock`'s default shadow offset is (1,1) even though the shadow is transparent.** A scroll measure built from `GetMaxCharacterHeight` alone comes up one unit short per line, and a long list then clips its last row with nowhere left to scroll.
- **A widget takes its face and its panel backing from the project's one shared owner of each** — never a font finder or a backing literal of its own, or the next restyle misses it.
- Author every colour constant as `FColor` sRGB bytes and decode with `FLinearColor(Colour)` at one point of use. A raw linear literal renders roughly a stop too bright and no headless spec can see it. **Price a UI colour against every ground it lands on** (a dark menu, a light panel): one accent has to clear both, so compute the contrast ratio on each rather than judging it on the darker one. **A painted ground is not one ground** - sample the art down the mark's whole length before choosing "darker than the ground".
- **Hue is NOT preserved by the sRGB↔linear transfer** - it is not a per-channel scalar, so `FLinearColor(Bytes).LinearRGBToHSV()` answers a different hue than the bytes do. Measure hue off the sRGB bytes: that is the space colours are chosen in.
- `UTextRenderComponent`'s engine-default visibility is TRUE — a hidden-until-opted-in component must call `SetVisibility(false)` in the constructor, not rely on a later data-driven update.
- 3D labels for a fixed-camera scene set a fixed WORLD rotation in `OnConstruction`; relative rotations inherit actor yaw and render upside-down on a mirrored side.
